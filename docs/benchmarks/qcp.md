# QCP Python 性能测试

在项目目录执行，无第三方依赖：

```bash
python benchmarks/python/qcp/benchmark_qcp.py
```

更充分的单线程极限吞吐及延迟测试（约 1 分钟以上）：

```bash
python benchmarks/python/qcp/benchmark_qcp.py --seconds 2 --stress-seconds 60 --samples 10000 --random-cases 10000 --output reports/benchmarks/python/qcp/benchmark_results.json
```

持续压测可以将 `--stress-seconds` 增加到 600 或更长。默认开启 Python 垃圾回收；可以另跑一轮添加 `--disable-gc` 比较。请在实际部署设备及对应 Python 环境中运行，后台负载、CPU 频率和温度会影响结果。

## 覆盖范围

- 解析切点、边界交点、顶点最优、不可行、空输入及退化线段。
- 近奇异半正定二次矩阵，以及退化为线性约束的情况。
- 4、8、16 顶点且每条边都有两个二次曲线交点的场景；目标方向使切点在多边形外，触发完整枚举。16 是当前实现的顶点容量上限。
- 固定随机种子的半正定约束输入，持续混合求解，观察运行波动。

先检查固定案例的可行性及已知目标值，再做计时。随机检查仅检查返回可行点的约束，不认证全局最优或不可行结论；发现异常会输出到 JSON 并以退出码 1 结束。

## 指标含义

- 平均耗时与吞吐：预构造输入、预热后批量调用 `solve()` 的实测结果。
- P50/P95/P99/最大延迟：另行逐次采样，完整值保存在 JSON 中；终端显示 P99 和最大值。
- 超预算：默认单次调用超过 1000 微秒的样本数，对应 1 kHz 周期的时间预算，可用 `--deadline-us` 调整。
- 持续压测：单线程无等待饱和运行，记录吞吐、批次吞吐范围、最大调用延迟和超预算次数。循环以 1000 次为一个批次，因此实际时间可能稍长于指定值。

计时包含 Python 调用及少量测量开销，不包含输入构造、半平面裁剪或控制循环其他工作。持续压测包含输入轮换和计时管理，其吞吐与单场景批量计时有所不同。空输入仅用于测量快速返回路径，不能作为正常求解吞吐的代表。

这些是当前环境下观测到的极限负载结果，不是数学上的最坏执行时间上界，也不能单凭压测保证硬实时调度。原算法的数值处理行为未作修改。
